# MacOSMdir MOM 제작 프롬프트

이 문서는 MOM 제작에 사용한 초기 구현 프롬프트에 후속 요구사항을 반영한 통합본입니다. 아래 내용을 구현 에이전트에게 전달하여 사용할 수 있습니다.

최종 반영 사항:

- 애플리케이션 이름은 **MacOSMdir MOM**입니다.
- 터미널 실행 명령, alias, 셸 래퍼 함수 이름은 **`m2`**입니다.
- 처음 실행할 때는 **1단 파일 목록**을 표시합니다.
- **Tab을 누르면 좌우 2단 패널**, 다시 누르면 1단으로 전환합니다.
- 각 패널 안의 파일 목록은 항상 1열이며, 터미널 너비에 따라 자동으로 2~4열을 만드는 동작은 사용하지 않습니다.

---

당신은 Python TUI, 크로스플랫폼 파일 시스템, 유니코드 터미널 렌더링에 능숙한 시니어 소프트웨어 엔지니어입니다.

1990년대 한국 DOS 파일 관리자 ‘Mdir III’에서 영감을 받은 현대적인 터미널 파일 관리자 **MacOSMdir MOM**을 구현하세요. 설명이나 설계 제안으로 끝내지 말고, 실제로 설치·실행할 수 있는 소스 코드, 테스트, 실행 가이드를 완성하세요.

참고 영상:
https://www.youtube.com/watch?v=bn3ZcI4q6Xo

영상에 접근할 수 있다면 실제 화면과 조작을 확인해 디자인에 반영하세요. 접근할 수 없다면 확인했다고 주장하지 말고 아래 요구사항을 기준으로 진행하세요. 확인되지 않은 역사적 동작은 현대적인 구현 선택과 구분해 기록하세요.

공식 Mdir의 소스 코드나 그래픽 자산을 복제하지 않고, 레이아웃·색상·키보드 조작에서 영감을 받은 독립 구현으로 만드세요. UI 언어는 한국어를 기본으로 합니다.

## 1. 기술과 산출물

- Python 3.11 이상과 Textual/Rich를 사용하세요.
- Python 패키지명은 `mom`, 프로젝트 배포명은 `macos-mdir-mom`으로 구성하세요.
- CJK 문자 너비 처리는 wcwidth 등 검증된 방법을 사용하세요.
- macOS를 우선 실행 환경으로 삼고 Linux, Windows에서도 실행할 수 있도록 플랫폼 의존 코드를 분리하세요.
- pyproject.toml에 console script **`m2`**를 등록하세요.
- requirements.txt, README.md, 전체 소스, 핵심 동작 테스트를 제공하세요.
- 현재 저장소가 있다면 기존 구조와 작업 지침을 먼저 확인하고 통합하세요.
- 실행과 검증까지 직접 수행하세요. 수행하지 못한 플랫폼 검증은 명시하세요.
- 구현 계획만 제시하거나 핵심 기능을 TODO, pass, 임시 데이터로 대체하지 마세요.

권장 모듈 구성:

- app: 앱 구성 및 키 바인딩
- models/filesystem: 파일 목록과 파일 작업
- widgets: 파일 목록과 정보창
- screens: 입력·확인·도움말 모달
- viewer: VV 텍스트 뷰어
- archives: 압축 가상 파일 시스템
- cli: 실행 옵션 및 종료 경로 기록

프로젝트 크기에 맞춰 구조는 조정해도 됩니다.

## 2. 시그니처 화면과 색상

기본 배경은 VGA 파랑 `#0000AA`입니다. 밝은 청록색과 흰색의 이중선 테두리 `╔ ═ ╦ ╗ ║ ╠ ╬ ╣ ╚ ╩ ╝`를 사용해 DOS 텍스트 모드 분위기를 재현하세요.

기본 화면:

- 상단: 앱 이름, 현재 경로, 정렬 방식
- 중앙: 하나의 패널에 한 열로 표시하는 파일 목록
- 우측 또는 하단: 선택 항목 정보, 디스크·시스템 요약
- 하단: 선택 개수와 용량, 여유 디스크 공간, 상태 메시지
- 마지막 줄: 기능키 안내

**초기 화면과 Tab 전환 규칙을 반드시 지키세요.**

- 최초 실행은 1단, 즉 하나의 파일 패널로 시작하세요.
- Tab을 누르면 좌우 2단 패널로 즉시 전환하세요.
- 다시 Tab을 누르면 1단으로 돌아오세요.
- 1단은 하나의 파일 목록이고, 2단은 좌우 두 개의 독립적인 파일 목록입니다.
- 각 패널 내부의 파일 목록은 항상 1열입니다. 화면이 넓어져도 파일 목록을 자동으로 여러 컬럼에 분산하지 마세요.
- 2단에서 Ctrl+Left / Ctrl+Right로 활성 패널을 전환하세요.
- 각 패널은 경로, 커서, 선택 상태를 독립적으로 유지하세요.
- 1단으로 돌아올 때 왼쪽 패널을 활성화하되 오른쪽 패널의 상태는 보존하세요.
- 2단의 복사·이동 대상 기본값은 반대편의 실제 디렉터리입니다.
- 1단에서는 대상 경로 입력창을 표시하세요.
- 화면 모드 안내, 도움말, README, 테스트도 이 규칙과 일치시키세요.

파일 항목은 이름, 확장자, 크기, 수정 날짜를 표시하세요. 좁은 화면에서는 날짜·확장자 등 부가 열을 순서대로 줄이고, 최소 지원 크기보다 작으면 안내를 표시하세요.

한글, 공백, 조합 문자, 이모지, 긴 경로가 있어도 테두리가 밀리지 않아야 합니다. 문자열 길이 len()을 표시 폭으로 사용하지 마세요. 축약, 패딩, 커서·선택 영역 모두 터미널 셀 너비를 기준으로 계산하세요. 문자 축약 시 하나의 그래핌을 중간에서 자르지 마세요. 파일명에 제어 문자나 터미널 이스케이프가 있어도 안전하게 표시하세요.

색상:

| 종류 | 색상 및 표시 |
|---|---|
| 디렉터리 | 굵은 밝은 노랑, `<DIR>` 표시 |
| 실행 파일 `.exe`, `.com`, `.sh`, `.app` 및 실행 권한 파일 | `#55FF55` |
| 스크립트 `.bat`, `.cmd`, `.py`, `.js` 등 | `#FFFF55` |
| 압축 `.zip`, `.tar`, `.gz`, `.7z`, `.lzh`, `.arj` 등 | `#FF55FF` |
| 문서 `.txt`, `.md`, `.doc`, `.hwp`, `.json` 등 | `#55FFFF` |
| 이미지·미디어 `.jpg`, `.png`, `.mp3`, `.mp4` 등 | `#FF5555` |
| 일반 파일 | `#AAAAAA` |

분류 우선순위를 명확히 정해 실행 권한이 있는 Python 파일도 일관되게 표시하세요. `.app` 디렉터리는 일반 디렉터리와 구별할 수 있게 처리하세요. 색상으로 구분하는 것과 실제로 열거나 실행할 수 있는 형식은 구분하세요.

## 3. 탐색과 키 바인딩

- ↑ / ↓: 이전 / 다음 항목
- ← / →: 이전 / 다음 페이지
- PgUp / PgDn: 페이지 이동
- Home / End: 처음 / 마지막 항목
- Enter:
  - 디렉터리: 진입
  - `..`: 상위 이동
  - 지원 압축 파일: 가상 디렉터리 진입
  - 텍스트 파일: VV 뷰어
  - 실행 파일: 실행 확인 후 실행
- Backspace: 상위 이동
- Space / Insert: 선택 토글 후 다음 항목으로 이동
- C / F5: 복사
- M / F6: 이동
- F2: 현재 항목 이름 변경
- D / Delete / F8: 삭제 확인
- K / F7: 디렉터리 생성
- V / F3: VV 뷰어
- F4: 외부 편집기
- A: 정렬 설정
- T / F9: MCD 트리
- F1: 도움말
- Q / F10: 종료
- Ctrl+R: 파일 목록 새로고침
- Esc: 모달 또는 압축 탐색을 닫고, 최상위 파일 화면에서는 종료

Tab은 1단 ↔ 2단 전환에 사용하고, 2단의 활성 패널 전환은 Ctrl+Left / Ctrl+Right로 처리하세요.

F10의 ‘트리’와 ‘종료’ 요구가 충돌하지 않도록 기본값은 F10=종료, T/F9=트리로 통일하세요. 문서, 도움말, 실제 바인딩, 하단 안내를 일치시키세요.

알파벳 명령은 대소문자 모두 지원하되 입력창과 뷰어 검색 중에는 문자 입력을 가로채지 마세요. 셸 실행 명령 **`m2`**와 앱 내부 이동 명령 **M**은 별개입니다. 실행 명령을 변경했다는 이유로 앱 내부 M 키를 변경하지 마세요.

빠른 점프:

- `/`: 이름 접두사 입력창
- 입력하면서 첫 일치 항목으로 이동
- Alt+문자: 해당 문자로 시작하는 항목으로 이동
- Alt 조합을 전달하지 않는 터미널에서는 `/`로 같은 작업 가능

정렬:

- 이름, 확장자, 크기, 수정 시각
- 오름차순 / 내림차순
- 디렉터리 우선
- `..` 항목은 맨 위 고정

## 4. 선택과 실제 파일 작업

선택 항목에는 `*`와 노란색 강조를 표시하세요. 하단에 선택 개수와 합산 크기를 표시하세요. 디렉터리 재귀 용량 계산으로 화면이 멈추지 않게 하고, 크기 집계 기준을 UI와 문서에 명확히 설명하세요.

선택 항목이 있으면 선택 집합에, 없으면 현재 항목에 작업하세요. `..` 항목은 선택·복사·이동·삭제 대상에서 제외하세요. F2는 현재 항목 하나의 이름을 변경하세요.

복사·이동·삭제:

- 파일과 디렉터리 지원
- 대상 경로 입력 및 `~`, 상대 경로 처리
- 기존 파일 충돌 시 덮어쓰기 / 건너뛰기 / 취소 선택
- 자신에게 복사하거나 디렉터리를 자기 하위로 옮기는 작업 차단
- 심볼릭 링크 처리 원칙 명시
- 작업 진행 상태와 항목별 실패 표시
- 대용량 작업은 백그라운드 워커에서 실행
- 작업 후 목록, 커서, 선택 상태 갱신
- 권한 오류, 파일 소실, 디스크 부족 등은 앱 종료 대신 오류 모달로 표시

삭제는 대상과 개수를 보여준 후 확인받으세요. 영구 삭제인지 휴지통 이동인지 명확히 표시하세요. 다중 파일 작업이 원자적으로 완료된다고 가정하지 마세요. 덮어쓰기 시 기존 데이터가 손실될 수 있는 구간을 줄이도록 임시 위치에 복사를 완료한 후 교체하는 방식을 사용하세요.

실행과 외부 편집기는 터미널을 올바르게 일시 반환하고 복구하세요. shell=True 문자열 연결을 사용하지 말고 경로를 안전하게 전달하세요. 외부 편집기는 VISUAL/EDITOR 설정을 우선 사용하고 플랫폼별 대안을 제공하세요. 파일명에 공백, 한글, 따옴표가 포함된 경우를 처리하세요.

## 5. VV 텍스트 뷰어

레트로 블루/그린 테마의 내장 뷰어를 구현하세요.

- 줄 번호
- 파일 경로와 인코딩 표시
- 현재 위치 퍼센트
- 방향키, PgUp/PgDn, Home/End
- `/` 검색, n 다음 결과, N 이전 결과
- 검색 결과 강조
- Esc/Q로 닫기
- UTF-8 BOM 및 UTF-8 우선 감지
- UTF-8 실패 시 CP949 시도
- 디코딩 실패 시 대체 처리 사실 표시
- 바이너리는 텍스트로 무조건 디코딩하지 않기
- 큰 파일은 읽기 한도 또는 점진 읽기로 메모리 폭증 방지

인코딩 감지는 휴리스틱이라는 점을 문서에 명시하세요. 줄 단위 탐색과 검색은 한글에서도 정상 동작해야 합니다.

## 6. MCD 디렉터리 트리

T/F9로 트리 팝업을 여세요.

- 현재 경로 중심으로 표시
- 화살표로 이동·확장·축소
- Enter로 선택 경로 진입
- Esc로 취소
- 상위 디렉터리로 트리 기준점 이동 가능
- 하위 디렉터리는 지연 로딩
- 권한 없는 경로는 오류 표시 후 탐색 계속
- 심볼릭 링크 순환 방지
- 전체 디스크 선행 스캔 금지

## 7. 압축 가상 폴더

ZIP과 TAR 계열 `.tar`, `.tar.gz`, `.tgz`를 실제 지원하세요. 색상 분류에 포함된 7z/lzh/arj까지 지원한다고 오해하게 만들지 마세요. 추가 형식이 미지원이면 이유를 표시하세요.

- Enter로 내부 탐색
- 디스크에 풀지 않고 디렉터리와 파일 목록 표시
- 명시적 디렉터리 엔트리가 없는 압축도 폴더 구조 구성
- `..`로 압축 내부 상위 이동
- 압축 루트에서 `..` 또는 Backspace로 호스트 디렉터리 복귀
- 내부 텍스트 파일을 VV로 열기
- C/F5로 선택 항목을 실제 경로에 추출
- 내부 수정·삭제·이동은 읽기 전용 안내
- 호스트 경로와 압축 내부 경로를 구분해 표시

추출 시:

- `../` 및 절대 경로를 통한 경로 이탈 차단
- Windows 드라이브 경로 등도 검사
- 심볼릭 링크·하드링크·특수 파일은 안전한 정책으로 처리
- 링크를 경유한 대상 디렉터리 이탈도 방지
- 항목 수와 해제 크기 한도 적용
- 실제 읽은 데이터 크기에도 한도 적용
- 전체 압축을 무조건 메모리에 로드하지 않기
- 충돌 시 덮어쓰기 동작과 폴더 병합 여부를 명확하게 안내

## 8. 상태창과 기능키 바

표시 정보:

- 현재 경로
- 현재 항목 정보
- 선택 개수와 합산 크기
- 현재 파일 시스템의 여유 공간
- 메모리 상태

메모리 조회는 플랫폼별 차이를 처리하고 조회 불가 시 N/A를 표시하세요. 필요하면 psutil을 의존성으로 추가하세요. 느린 디스크·네트워크 경로의 정보 조회로 UI가 멈추지 않게 하세요.

기능키 바:

```text
F1 도움말 | F2 이름변경 | F3 보기(VV) | F4 편집 |
F5 복사 | F6 이동 | F7 폴더생성 | F8 삭제 |
F9 트리(MCD) | F10 종료
```

좁은 화면에서는 짧은 라벨이나 두 줄 배치로 조정하세요. 정렬 메뉴와 확인창도 최소 지원 크기에서 모든 선택지에 키보드로 접근할 수 있어야 합니다.

## 9. `m2` 실행과 셸 디렉터리 유지

다음 실행 방식을 제공하세요.

- `python -m mom`
- `pip install -e .` 이후 **`m2`**
- 선택적 `alias m2='python -m mom'`

console script는 `m2`로 등록하세요. 기존 `m` 실행 명령을 대체하며, 문서와 셸 스크립트의 명령 이름도 `m2`로 통일하세요. Python 모듈 실행 옵션 `-m`은 그대로 유지하세요.

부모 셸의 현재 디렉터리를 Python 자식 프로세스가 직접 바꿀 수 없다는 점을 설명하세요.

CLI 옵션:

- 시작 경로 인자
- `--last-dir-file PATH`: 정상 종료 시 마지막 실제 디렉터리 기록
- `--print-last-dir`: TUI 복구 후 마지막 경로 출력
- `--version`, `--help`

압축 내부에서 종료하면 대응하는 호스트 디렉터리를 기록하세요.

README에 복사해서 사용할 수 있는 셸 래퍼와 설정 가이드를 제공하세요.

- bash/zsh의 **`m2()`** 함수
- PowerShell의 **`function m2`**

래퍼는 다음을 보장해야 합니다.

- 사용자 인자를 그대로 전달
- 안전한 임시 파일 사용
- 실제 실행 파일과 함수 이름의 재귀 호출 방지
- bash/zsh에서는 `command m2`로 실행 파일 호출
- PowerShell에서는 애플리케이션 실행 파일을 찾아 호출
- 경로 공백·한글·개행 보존
- 성공 종료 및 유효한 기록 경로 확인 후 cd/Set-Location
- 임시 파일 정리
- 셸 설정 파일을 자동으로 수정하지 않기

단순 alias 방식과 디렉터리 유지 래퍼 방식은 대안으로 설명하세요. 동일한 이름의 alias와 함수를 함께 설정해서 충돌하지 않도록 하세요.
